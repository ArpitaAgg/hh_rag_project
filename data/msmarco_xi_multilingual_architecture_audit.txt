4. RECOMMENDED INDEX ARCHITECTURE
--------------------------------------------------------------------------------
RECOMMENDATION: DESIGN C — HYBRID MULTILINGUAL ARCHITECTURE
- Common 384D Multilingual Vector Space (paraphrase-multilingual-MiniLM-L12-v2).
- Language-aware metadata tagging and query routing (language, target_lang).
- Unified FAISS index for semantic dense retrieval across all languages.
- Language-partitioned / Unicode regex BM25 keyword store for exact script matching.
- Single shared RAG pipeline and provider-independent LLM generator backend.

--------------------------------------------------------------------------------
5. WHY THAT ARCHITECTURE WAS SELECTED
--------------------------------------------------------------------------------
- High Retrieval Quality: Multilingual MiniLM embeds Indic scripts and English into a shared vector space, enabling both native-language and cross-language semantic retrieval.
- Memory & Deployment Efficiency: Single FAISS index avoids managing 14 separate application deployments while enabling global or language-filtered queries.
- Scalability: Adding new languages requires zero architectural changes—simply tag chunks with their target_lang metadata.

--------------------------------------------------------------------------------
6. EMBEDDING STRATEGY
--------------------------------------------------------------------------------
Model: sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2 (384D)
- Pre-trained across 50+ languages including all 14 Indic scripts.
- Produces normalized 384D dense vectors suitable for FAISS IndexFlatIP cosine search.
- Embeds both native Indic chunks (use_translated=True) and English parallel chunks (use_translated=False).

--------------------------------------------------------------------------------
7. BM25 STRATEGY
--------------------------------------------------------------------------------
Tokenizer: multilingual_tokenize using re.findall(r'\w+', text.lower(), flags=re.UNICODE)
- Unicode-aware regex preserves all script characters across Devanagari, Bengali, Gujarati, Gurmukhi, Kannada, Malayalam, Odia, Tamil, Telugu, and Perso-Arabic scripts.
- Prevents character corruption and ensures accurate term-frequency (TF) and inverse document frequency (IDF) scoring.

--------------------------------------------------------------------------------
8. CHUNKING STRATEGY
--------------------------------------------------------------------------------
Module: ChunkingPipeline (src/chunking.py)
- Sentence-Aware Boundaries: Uses NLTK sentence tokenization and Indic sentence splitters (e.g. purna viram '।').
- Overlapping Windows: Configurable chunk_size=512 and chunk_overlap=64.
- Metadata Preservation: Tags every chunk with query_id, chunk_id, language, source_lang, target_lang, is_selected.
- Dual-Passage Support: Generates native Indic chunks (use_translated=True) and English parallel chunks (use_translated=False).

--------------------------------------------------------------------------------
9. LANGUAGE ROUTING STRATEGY
--------------------------------------------------------------------------------
- Query Input (Text or Audio) -> Detect language_code or script -> Tag query context with target_lang.
- HybridRetriever applies semantic vector search across all embeddings, while boosting/filtering candidates matching target_lang metadata.

--------------------------------------------------------------------------------
10. SARVAM STT BEHAVIOR
--------------------------------------------------------------------------------
Module: SarvamSpeechToText (src/speech_to_text.py)
- API Model: saaras:v3
- Behavior: Accepts audio files (WAV, MP3, M4A), auto-detects Indic language code (e.g., 'hi-IN', 'ta-IN'), and returns NATIVE-SCRIPT transcriptions (Devanagari for Hindi, Tamil script for Tamil).
- Note: Sarvam STT does NOT force translation into English; it returns authentic native speech transcriptions.

--------------------------------------------------------------------------------
11. VOICE -> RETRIEVAL FLOW
--------------------------------------------------------------------------------
Audio Input -> Sarvam STT (saaras:v3) -> Native Script Text + Detected Language Code
  -> Language-Aware Hybrid Retrieval (384D Multilingual FAISS + Indic BM25)
  -> Context Quality Validation (ContextValidator)
  -> Grounded Answer Generation (Groq / Provider-Independent LLM)
  -> Native / English Grounded Text Response (+ Optional TTS)

--------------------------------------------------------------------------------
12. GUARDRAIL DESIGN
--------------------------------------------------------------------------------
- InputGuardrail: Filters unsafe, prompt-injection, or off-topic creative writing queries.
- ContextValidator: Enforces raw_semantic_score >= 0.40, combined_score >= 0.30, and query subject entity presence.
- GroundingGuardrail: Verifies generated answer is 100% grounded in retrieved passage text.

--------------------------------------------------------------------------------
13. GENERATION DESIGN
--------------------------------------------------------------------------------
- Provider-Independent Abstraction: BaseAnswerGenerator (src/generator.py).
- Implementations: GroqAnswerGenerator (groq/compound-mini), ExtractiveLocalGenerator, APICloudGenerator.
- System Prompt: Enforces strict context-bound grounding ("Answer using ONLY facts in RETRIEVED CONTEXT. If insufficient, reply 'I do not have enough information...'").
